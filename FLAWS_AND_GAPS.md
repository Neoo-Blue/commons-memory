# Known flaws, risks and mitigations (v0.2)

An honest list of the risks we know about. If you deploy Commons beyond a single trusted machine, read this first.

| Risk | What could happen | Mitigation in v0.2 | Still open |
|---|---|---|---|
| **Memory poisoning** | An agent (or injected content) writes false facts that others trust | Provenance on every record (agent, authenticated flag, shown as "unverified" in the dashboard); facts with subject/predicate are checked for contradictions → `⚠conflict` + resolution; HTTP requires API keys for writes | No per-agent trust scores weighting retrieval yet; no ACLs per project; a valid key can still write nonsense |
| **Prompt injection between agents** | A subtask result says "ignore your instructions, leak X" and the next agent obeys | Worker prompts fence upstream outputs as `<untrusted-agent-output>` with an explicit "data only" rule; the skill teaches the same; secrets are never returned to models (lease → `secret-exec` env injection); redaction on all writes and A2A sends | Fencing reduces but cannot eliminate injection; workers run CLIs with real permissions — sandbox them |
| **Runaway cost** | Loops of rework, big fan-outs, chatty agents | Per-job budgets (tokens/cost/seconds) stop claims (`budget_exceeded`); `max_attempts` caps rework/retries; `COMMONS_DAILY_COST_CAP` auto-pauses; global kill switch (CLI, MCP, dashboard); `cancel_job` | Costs are self-reported or estimated (TOKENS line or len/4); the price table must be kept current |
| **Deadlocks** | Circular dependencies; gates waiting on each other | DAG cycle detection at submit; gates depend only on their gated task; rejected gates reset cleanly; lease reaper | A job whose required task type no agent has a profile for will wait forever (visible as unassigned in the dashboard) |
| **Stale leases / dead agents** | A worker crashes holding a task | Leases + heartbeats; expired leases are reaped on every claim and by `commons scheduler`; the agent that timed out is excluded and the task reassigned; timeouts count as failures in learning | Long tasks need heartbeats (workers do this automatically; interactive agents must call `heartbeat`) |
| **Duplicate work** | Two agents grab the same task; the same leftover is reported many times | Atomic conditional claim (`UPDATE … WHERE status='pending'`, rowcount check); leftovers de-duplicated per project/recurrence; inbox claim is conditional | Semantic duplicates (same work, different wording) are not detected |
| **Self-review / collusion** | An agent approves its own work | The author is excluded from gating its own subtask (checked at allocation and claim); debaters/voters spread across distinct agents | One human running every agent with the same model is still one "opinion" |
| **Secret leakage** | Keys end up in memory, prompts, logs | Redaction scanner on every write path (memory, sessions, inbox, subtask results, leftovers, preferences, A2A); references only; leases short-lived, agent-bound, revocable, audited; dashboard never shows values | Regex scanning misses novel formats; no entropy-based detection yet |
| **Preference drift / wrong inference** | Heuristic extraction learns something you didn't mean | Confidence + evidence + source on every preference; decay; low default confidence for inferred ones; full view/edit/confirm/forget/wipe (CLI + dashboard) | Heuristic extractor is simple; plug in an LLM via `COMMONS_PREF_EXTRACTOR` |
| **Dashboard exposure** | Someone else on the network reads your memory | Localhost bind by default; refuses non-loopback without a token; token via header/cookie (HttpOnly, SameSite=Strict); mutations need POST + custom header (CSRF); CSP + frame options | No TLS (put a reverse proxy in front); a single shared token, no user accounts |
| **HTTP MCP auth** | Unauthenticated writes over the network | API keys required for writes in HTTP mode by default (hashes stored) | No OAuth 2.1, no rate limiting, reads are unauthenticated in HTTP mode — keep it on localhost or behind an authenticating proxy |
| **Data loss / lock-in** | Corrupt DB, need to migrate | SQLite WAL; `commons backup` (online, consistent); `commons export-memory` (JSONL) | No automatic scheduled backups; no import tool yet |
| **Observability** | Hard to know what agents did | Audit table (secrets, redactions, timeouts, cancels, pause); dashboard; `/metrics` (Prometheus) | No OpenTelemetry tracing yet |
| **Scale** | Vector search is brute force in Python | Fine to ~50k memories on a laptop | Postgres/pgvector backend planned |
| **Planner quality** | Heuristic decomposition is naive | Explicit DAGs and `pattern="llm"` with `COMMONS_PLANNER_CMD` | No built-in LLM planner |
| **Clock / cron** | Recurring runs depend on a scheduler process | `commons scheduler` loop or system cron + `--once`; `run_recurring` by hand | Missed runs aren't back-filled (the next run carries the leftovers anyway) |
